    \section{Methods}
        For all the methods below, the following boundary value problem identified as
        \begin{align}
            \begin{cases}
            \displaystyle
            \frac{d \mathbf{y}}{dz} = \mathbf{f}\bigl(z, \mathbf{y}(z)\bigr) \\
            \mathbf{y}(0) = \boldsymbol{\alpha}, \quad \mathbf{y}(H) = \boldsymbol{\beta},
            \end{cases}
            &&
            \begin{matrix}
            \left(\text{component units of }\mathbf{y}\,\unit{m^{-1}}\right)\\
            \left(\text{component units of }\mathbf{y}\right)
            \end{matrix}
        \end{align}
        There are multiple methods that solve the boundary value problem required when simulating an packed-absorption column. Three possible methods are introduced and analyzed: the shooting method, finite difference method, and collocation boundary-value method. In this benchmark, shooting and finite difference are comparison methods because they expose different initialization and discretization behavior on the same equations, while the collocation method is the current reference solver because it is the implementation used to generate the benchmark rows and report mesh and residual metadata. The paper therefore treats speed and robustness as empirical outcomes of the recorded runs, not as a priori method rankings.

        \subsection{Shooting Method}
            The shooting method is a powerful numerical technique for solving boundary value problems (BVPs) by converting them into an equivalent set of initial value problems (IVPs). The core idea is to guess any unknown initial conditions (such as a missing initial slope) and then integrate the differential equations forward in one ``shot,'' checking at the end whether the boundary conditions are satisfied. If the final boundary conditions are not met, the initial guess is refined, and the process is repeated. This approach leverages well-established methods for solving IVPs (such as the Runge--Kutta family of methods) while systematically adjusting the guess until the boundary constraints are fulfilled, typically by employing a root-finding algorithm (e.g., Newton--Raphson, bisection, or secant method) on the difference between the solution and the desired boundary value at the final point. One of the advantages of the shooting method is its conceptual simplicity: one only needs to implement a standard IVP solver and a root-finding procedure to iteratively converge upon the correct boundary values. However, it can be sensitive to numerical stability issues, especially if the BVP spans a large domain or if the underlying differential equations are stiff. Despite these limitations, the shooting method remains a popular and straightforward choice for many two-point BVPs, offering an intuitive framework to find solutions by effectively ``aiming'' from one boundary toward the other and iterating until the solution ``hits'' the required condition. Below is an overview of how to apply the shooting method to the boundary value problem (BVP):

            \subsubsection*{Integrate as an IVP (``Shoot'')}
                For a given guess $\mathbf{p}$:
                \begin{enumerate}
                    \item Construct the initial condition $\mathbf{y}(0) = \boldsymbol{\alpha}$.
                    \item Integrate the ODE system $\frac{d\mathbf{y}}{dz} = \mathbf{f}(z,\mathbf{y})$ from $z=0$ to $z=H$ using an IVP solver (e.g., a Runge--Kutta method).
                    \item Record the final solution $\mathbf{y}(H;\mathbf{p})$ at $z=H$.
                \end{enumerate}
                This completes one \emph{shoot} from $z=0$ to $z=H$.

            \subsubsection*{Mismatch Function}
                After integrating with the guess $\mathbf{p}$, define the \emph{mismatch function}:
                \begin{align}
                    \mathbf{F}(\mathbf{p}) = \mathbf{y}\bigl(H; \mathbf{p}\bigr) - \boldsymbol{\beta}
                    && \left(\text{component units of }\mathbf{y}\right).
                \end{align}
                This vector $\mathbf{F}(\mathbf{p})$ measures how far the computed solution at $z=H$ is from the required boundary condition $\boldsymbol{\beta}$.

            \subsubsection*{Root-Finding on the Mismatch}
                To solve the BVP, we need $\mathbf{F}(\mathbf{p}) = \mathbf{0}$. Thus, the unknown initial values $\mathbf{p}$ must be adjusted until
                \begin{align}
                    \mathbf{y}\bigl(H,\mathbf{p}\bigr) &= \boldsymbol{\beta}
                    && \left(\text{component units of }\mathbf{y}\right).
                \end{align}
                Any standard root-finding algorithm capable of handling multiple variables can be used here. Each iteration calls the IVP solver anew (the ``shoot''), refines $\mathbf{p}$, and re-checks the mismatch at $z=H$ until $\|\mathbf{F}(\mathbf{p})\|$ is sufficiently small.

            \subsubsection*{Summary}
                The shooting method, while conceptually straightforward, can encounter several complications when applied to a system of this nature. First, if the underlying equations are stiff or exhibit rapid changes, small numerical inaccuracies in the guessed initial conditions can amplify significantly over the integration domain, making the procedure unstable or very sensitive to perturbations. Second, if the domain is large or the solution features steep gradients, one might need a very accurate or adaptive IVP solver for each ``shoot,'' which can be computationally expensive. Additionally, good initial guesses for the unknown boundary conditions may be hard to find, especially in higher-dimensional problems, which can increase iteration counts. Finally, repeated integration for each iteration of a root-finding method (e.g., Newton's method or secant-like approaches) can become costly, and if Jacobian information is not readily available, approximation errors in the gradient of the mismatch function can slow the solve. These characteristics matter when solving the boundary value problem due to the stiffness and non-linearity of the model and will be further discussed below.

        \subsection{Finite Difference}
        The finite difference method (FDM) approximates derivatives with discrete difference quotients across a spatial mesh. By discretizing each differential equation between the boundary conditions, the original BVP is transformed into a system of algebraic equations. Each unknown state is represented at the mesh nodes, and finite-difference formulas link neighboring nodal values. The boundary conditions then anchor the solution at the domain edges. For the absorber model, the finite-difference system includes the species flow rates, phase enthalpy flows, and pressure state, coupled through the original differential equations. The method's main advantages are clarity of formulation and straightforward extension to mixed boundary conditions. Its main challenges are grid sensitivity, nonlinearity, stiffness, and the computational cost of solving the coupled algebraic system. The implementation steps are summarized below.

            \subsubsection*{Discretize the Domain}
                Divide the interval $[0,H]$ into $N$ sub-intervals of equal length $\Delta z = \frac{H}{N}$. Define the grid points:
                \begin{align}
                    z_k = k\,\Delta z, \quad k = 0, 1, 2, \ldots, N,
                    && \left(\unit{m}\right)
                \end{align}
                so that $z_0 = 0$ and $z_N = H$. Let $\mathbf{y}^k$ be the approximation to $\mathbf{y}$ at $z = z_k$:
                \begin{align}
                    \mathbf{y}^k \;\approx\; \mathbf{y}\bigl(z_k\bigr)
                    && \left(\text{component units of }\mathbf{y}\right).
                \end{align}
                Each component of $\mathbf{y}^k$ corresponds to one of the six unknown functions ($F^{\liq}_{\mathrm{CO_2}}$, $F^{\liq}_{\mathrm{H_2O}}$, $F^{\vap}_{\mathrm{CO_2}}$, $F^{\vap}_{\mathrm{H_2O}}$, $\dot{H}_l$, $\dot{H}_v$).

            \subsubsection*{Approximate Derivatives by Finite Differences}
                A common choice is to use central differences for interior points:
                \begin{align}
                    \frac{d \mathbf{y}}{dz}\biggr\rvert_{z=z_k}
                    \approx
                    \frac{\mathbf{y}^{k+1} - \mathbf{y}^{k-1}}{2\,\Delta z},
                    \quad 
                    k = 1, 2, \ldots, N-1
                    && \left(\text{component units of }\mathbf{y}\,\unit{m^{-1}}\right).
                \end{align}
                If your system dictates or if you prefer simpler expressions, you might use forward or backward differences in some cases, but central differences typically provide higher accuracy for the same grid spacing. Thus, for each $k=1,\dots,N-1$, we replace \(\frac{d \mathbf{y}}{dz}\bigl(z_k\bigr)\) with the discrete difference. This transforms each continuous ODE \(\frac{d y_i}{dz} = f_i\bigl(z, y_1, y_2, \ldots, y_6\bigr)\) into an algebraic equation involving $\mathbf{y}^{k-1}$, $\mathbf{y}^k$, and $\mathbf{y}^{k+1}$.

            \subsubsection*{Impose Boundary Conditions}
                At $k=0$ and $k=N$, apply the boundary conditions:
                \begin{align}
                    \mathbf{y}^0 = \boldsymbol{\alpha}, 
                    \quad 
                    \mathbf{y}^N = \boldsymbol{\beta},
                    && \left(\text{component units of }\mathbf{y}\right)
                \end{align}
                or, if only some components are known at each boundary, then only those components in $\mathbf{y}^0$ or $\mathbf{y}^N$ are fixed and the remaining must be determined by the system of equations.

            \subsubsection*{Solve the Resulting System of Nonlinear Algebraic Equations}
                Assemble all interior finite-difference approximations (one for each equation at each interior grid point), together with the boundary conditions at $k=0$ and $k=N$, into a large system of algebraic equations. Denoting the unknowns by \(\bigl(\mathbf{y}^1, \mathbf{y}^2, \dots, \mathbf{y}^{N-1}\bigr)\), the total number of unknowns is $7 \times (N-1)$ if all seven state variables are unknown at each interior node (assuming boundary values at $k=0$ and $k=N$ are given). If some boundary values are unknown, then the count of unknowns will adjust accordingly. In any case, the final step is to solve
                \begin{align}
                    \mathcal{R}\Bigl(\mathbf{y}^0,\, \mathbf{y}^1,\, \dots,\, \mathbf{y}^N\Bigr) 
                    = \mathbf{0},
                    && \left(\text{component residual units}\right)
                \end{align}
                where $\mathcal{R}$ denotes the collection of finite-difference equations plus boundary conditions.

            \subsubsection*{Summary}
                By ensuring appropriate grid resolution and an effective nonlinear solver, finite difference approximations can provide accurate, stable solutions to this system of differential equations across the domain $0 \le z \le H$. While this technique can be both robust and straightforward conceptually, it comes with its own potential pitfalls. For instance, a too-coarse grid can lead to poor accuracy or even instability when applied to stiff or highly nonlinear systems. As the mesh becomes finer, the number of equations to be solved grows quickly, which can increase computational cost substantially, especially for higher-dimensional systems. Additionally, nonlinearity may require iterative solvers like Newton's method at each time step or iteration, and assembling and factoring large Jacobians can be computationally intensive. Boundary conditions that are non-standard or mixed in form may also complicate the discretization scheme. Overall, while the finite difference method is a powerful approach, the choice of mesh, solver, and stability considerations must be carefully addressed for each specific problem.

        \subsection{Collocation BVP Method}
            The current collocation implementation uses the \texttt{scipy.integrate.solve\_bvp} package routine, which solves boundary-value problems with residual control and adaptive mesh refinement. This method is distinct from a custom orthogonal collocation implementation based on explicitly selected Legendre or Chebyshev points. For reproducibility, the benchmark reports the starting mesh size, maximum node count, solver tolerance, boundary-condition tolerance, initialization profile, scaling, final residual norm, and convergence message used for each run.

            \subsubsection*{Mesh and Initial Profile}
                The collocation method starts from a finite axial mesh across the packed height and an initial profile for every state variable on that mesh. For the absorber model, the state profile includes the liquid and vapor apparent molar flow rates, liquid and vapor enthalpy flows, and pressure. The initial profile can be constant, linearly interpolated between boundary values, or reused from a nearby operating point. This initialization matters because reaction equilibrium, fugacity, enhancement-factor, and transport calculations are all nonlinear functions of the local state. A poor initial profile can place some mesh intervals outside the physically meaningful domain, while a profile that respects inlet flows, temperatures, and pressure gives the nonlinear solver a better starting point.

            \subsubsection*{Local Polynomial Representation}
                Instead of integrating the model from one boundary to the other, the collocation method represents each state variable by piecewise polynomial functions over the mesh intervals. Within each interval, the algorithm chooses internal collocation points and requires the polynomial derivative to agree with the governing ODE residual at those points. The boundary conditions are enforced at the ends of the domain at the same time. This converts the two-point BVP into one coupled nonlinear algebraic problem for the unknown state values and polynomial coefficients across the whole column. The important distinction from shooting is that both column ends influence the solution simultaneously; the method does not rely on guessing one boundary and propagating the entire profile in one direction.

            \subsubsection*{Nonlinear Iteration and Residual Control}
                The coupled algebraic system is solved iteratively. At each iteration, the model evaluates the governing-equation residuals, boundary residuals, and any scaling used to make the variables comparable in magnitude. The iteration then updates the mesh-state values so that the polynomial profile better satisfies the differential equations and boundary conditions. For this absorber model, the residual evaluation is expensive because each axial point requires chemical-equilibrium, thermodynamic driving-force, transport-property, enhancement-factor, and flux calculations. The benchmark therefore records not only convergence success, but also the residual norm, boundary-condition residual, runtime, mesh size, and solver message.

            \subsubsection*{Adaptive Mesh Refinement}
                After a candidate solution is found on the current mesh, the method estimates where the collocation residual is largest. Intervals with larger residuals are refined by adding more mesh nodes, and the nonlinear solve is repeated on the refined mesh. This adaptivity is useful for packed-column absorption because temperature and concentration profiles can be smooth in most of the bed but sharper near a thermal bulge or thermodynamic pinch region. A fixed coarse mesh can miss these regions, while an unnecessarily fine uniform mesh increases the nonlinear system size everywhere. The adaptive approach concentrates nodes where the solution needs them, subject to the maximum-node limit reported in the benchmark.

            \subsubsection*{Benchmark Role}
                In this work, the collocation method is treated as one solver configuration in the benchmark rather than as a separate methodological contribution. It is the primary workflow for the NCCC one-bed validation because it handles mixed boundary conditions and localized profile changes more reliably than propagating an initial-value guess through the full column. This does not make it universally superior: its performance still depends on scaling, initialization, mesh limits, residual tolerances, and whether the property models remain inside their valid domains. The benchmark output records its tolerance settings, adaptive mesh behavior, convergence message, boundary residual norm, runtime, and validation error so that claims about robustness or speed are traceable to reported results.

        \subsection{Reproducibility and Numerical Settings}
            The benchmark calculations were performed in a Python 3.13 environment with fixed package versions. Each result entry records the case and method configuration, convergence message, residual metadata, capture error, temperature error where measured taps are available, runtime, mesh settings, solver tolerances, initialization notes, and thermodynamic model. Environment metadata, including Python version, platform, and package versions, is retained with the full benchmark dataset used to generate the reduced paper-facing tables. The same reporting schema is used for all solver paths so numerical behavior can be compared without relying on qualitative descriptions alone.

            The thermodynamic benchmark includes the baseline Henry-law model and a neutral ePC-SAFT sensitivity model. In the ePC-SAFT lane, the equation-of-state package is used as a fugacity-coefficient calculator while the legacy chemical-equilibrium calculation remains active. Only the CO$_2$ fugacity driving force is changed; chemical equilibrium, enhancement factor, transport-property correlations, and governing balances are held fixed. Pressure is specified for each ePC-SAFT phase state, and density initialization is treated as a numerical acceleration rather than a change in thermodynamic model. These ePC-SAFT results are therefore controlled thermodynamic sensitivity studies and not full electrolyte-reactive thermodynamic models.
